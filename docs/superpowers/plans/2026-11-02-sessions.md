# Sessions (DB-backed) Implementation Plan

**Goal:** Store authenticated sessions in SQLite, list them at `/app/settings`, and let users revoke one device or all other devices.

**Spec:** `docs/superpowers/specs/2026-11-02-sessions-design.md`

## Global Constraints

- No new dependencies.
- Anonymous sessions must not create database rows.
- Authenticated session data lives only in the `sessions` table; the cookie holds `db:<id>`.
- Session lifetime: 30 days (cookie `maxAge` and server-side idle timeout).
- Revoke must verify ownership.
- Tests use the in-memory database and assert redirect targets.

### Task 2: Hybrid session storage

**Files:** `app/data/session-storage.ts`, `app/data/session-storage.test.ts`

- [x] **Step 1:** Implement `createHybridSessionStorage()` as a `SessionStorage`:
  - `read('db:<id>')` loads the row and returns `createSession(id, data)`.
  - Anonymous cookie values fall back to `createCookieSessionStorage()`.
  - Missing, malformed, expired, or revoked ids return a fresh anonymous session.
  - Authenticated saves insert/update the row and return `db:<id>`.
  - Destroyed sessions delete the row and return `''`; unchanged sessions return `null`.
  - `regenerateId(true)` deletes the previous row.
- [x] **Step 2:** Capture IP and User-Agent with `AsyncLocalStorage` on session creation.
- [x] **Step 3:** Update `last_active_at` at most every 5 minutes on read.
- [x] **Step 4:** Add the 30-day idle timeout: delete a row older than the TTL on read; prune expired rows when creating a new DB session.
- [x] **Step 5:** Tests: anonymous visits create no rows; login creates exactly one row; expired rows are dropped; active rows are read.
